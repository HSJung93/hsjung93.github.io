## 상황: 기존 게이트웨이 과부하 + SSE(Server-Sent Events) 신규 요구가 겹침



## 분리 결정: 웹 서비스 전용 게이트웨이를 따로 두는 경계. 무엇을 넘기고 무엇을 남겼나



## Spring Cloud Gateway 선택 이유 (Reactive, 필터 모델). 대안은 무엇이었나



## 책임 분리: SSL 종료, 토큰 인증, 라우팅. 필터 체인 구성



## Reactive 환경에서 SSE 를 통과시키며 겪은 것 (버퍼링, 타임아웃, 커넥션 유지)



## 관측: 네이티브 메트릭으로 Grafana 대시보드를 만든 이유와 보는 지표



## 교훈: 게이트웨이는 기능이 아니라 경계다
