## 레거시 인증 교체 과제의 범위. 토큰에 클레임이 쌓여 비대해지고 평문으로 다니던 문제



## 서명(JWS)만으로 부족했던 이유: 토큰 안 정보 노출. JWE 선택과 알고리즘 조합(키 관리·키 교체는 어떻게)



## 걱정: 암복호화가 모든 요청에 붙는다. 지연이 얼마나 늘까



## k6 시나리오 설계: 어떤 요청 패턴, 어떤 지표(p95·처리량), 비교 대상(JWS vs JWE)



## 결과와 판단: 늘어난 지연이 허용 범위였는지, 토큰 크기 변화, 어디서 타협했나



## 같은 과제 안의 다른 결정: 캡차·로그인 정보 동기화 API 에 비동기 처리를 넣은 이유와 효과
