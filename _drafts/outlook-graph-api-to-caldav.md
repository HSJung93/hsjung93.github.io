## 사용자 증가 정체. Outlook 사용자를 끌어오려면 연동이 필요했다



## 두 세계의 모델 차이: Graph API 이벤트 vs CalDAV/iCalendar (반복 규칙, 타임존, 예외 일정, 참석자)



## 변환을 어디서 하나: 클라이언트 vs 서버 사이드. 서버를 택한 이유



## 가장 괴로웠던 변환 2가지 (반복 일정의 예외, 타임존 경계 등 당시 사례)



## 결과: 20만 명 이상 신규 연동. 그 뒤에 온 유지보수 문제: 순환 의존, 2,000개 넘는 단위 테스트



## Spring Batch 이관 → 헥사고날 아키텍처 리팩터. 어댑터를 분리하며 순환 의존을 끊은 과정



## 복잡한 시스템을 팀에 남기기: 아키텍처·도메인(Artemis, CalDAV, iCalendar, Timezone) 시각화 문서와 신규 구성원 설명회



## 교훈: 프로토콜 번역 계층은 "어느 쪽 모델이 정본인가"를 먼저 정해야 한다
