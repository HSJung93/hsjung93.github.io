## 출발점: VS Code 의 Claude Code 확장. 한 레포, 한 세션, diff 를 한 줄씩 보며 승인하던 시기



## 바뀐 신호 1: 세부 코드를 봐야 할 일이 줄었다. 왜 줄었나 (테스트·커버리지 게이트, MR 4단 본문, 역치환·양방향 EXCEPT 같은 "사람이 안 봐도 같다고 증명되는 장치"가 먼저 생겼다)



## 바뀐 신호 2: 병렬로 돌릴 일이 많아졌다. 파이프라인 저장소·대시보드·분석 코드·위키 스킬처럼 서로 독립인 작업이 하루에 여러 개



## 정착한 형태: herdr 로 여러 레포에서 CC 를 동시에 (구성 요지: 세션 분리, 작업 지시 단위, 결과 확인 방식)



## 내가 보는 것이 바뀌었다: 코드 → MR 본문·테스트 결과·미검증 표. 리뷰의 단위가 "줄"에서 "주장과 증거"로



## 그래도 에디터로 돌아가는 순간: 설계가 흔들릴 때, 처음 보는 코드베이스, 디버깅이 한 지점에 모일 때



## 비용과 함정: 토큰, 컨텍스트 분산, 서로 다른 세션이 같은 파일을 건드릴 때, "내가 모르는 코드"가 쌓이는 속도
